## [v0.8.0-rc.1] — 2026-10-05
### Added
- powerlab-mcp: `prompt://debug_unhealthy_service` — encodes the get_system_health → journal_search → check_disk_free diagnostic chain. Optional service (gateway, core, app-management, user) narrows the journal filter; since_minutes scopes the window. Pre-empts the common "service bug" misdiagnosis when the real cause is host capacity.
- powerlab-mcp: dedicated README at `backend/powerlab-mcp/README.md` — full inventory of the 9 read-only Tools + 3 opt-in Tools + 4 Prompts + ~20 Resources, transport (Streamable HTTP on /mcp), capability tiers, and mcp.conf reference. Indexed by MCP directories that scan repo subdirs.
- powerlab-mcp: demo image build + GHCR workflow. `Dockerfile.demo` produces a static MCP server image with the curated 44-app catalog, audit + journal seeds, and read-only config baked in. `.github/workflows/release-mcp-demo-image.yml` publishes `ghcr.io/<owner>/powerlab-mcp-demo:latest` (+ `:v<X.Y.Z>` on release tags) for multi-arch (amd64, arm64). Unlocks the Glama "release" requirement that gates TDQS + Coherence scoring on the directory listing.
- powerlab-mcp: demo seed fixtures at `backend/powerlab-mcp/demo/` — 44-app catalog-pick list, 50-line audit.jsonl, and 3 PowerLab service journals (gateway/app-management/mcp). Bakes into the upcoming demo image so an isolated MCP sandbox sees substantial Tool responses. Each fixture is shaped to surface a Prompt-encoded Tool chain (failed install → troubleshoot_install_failure, etc.). No code changes.
- powerlab-mcp: error-sanity audit + regression-test suite. Documents that no agent-visible Tool output leaks language-internal noise (subprocess wrap, runtime panic strings, Go install paths). Locks the contract in `server/tools_error_sanity_test.go` with a shared forbidden-substring list every new Tool must respect. Pre-existing `journal_search` classifier (5 tests) joined by a new `browse_catalog` regression covering missing-catalog-dir paths.
- powerlab-mcp: `backend/powerlab-mcp/glama.json` declares maintainer for the Glama MCP directory listing. Removes the "No glama.json" deficiency from the directory checklist.
- powerlab-mcp: `prompt://onboard_new_powerlab_host` — first-run walkthrough chaining list_capabilities → browse_catalog → get_system_health, with optional goal (free-text intent) + experience_level (beginner/intermediate/expert) for tone/depth tuning. Gives a fresh-host agent a guided tour before any install attempt.
- powerlab-mcp: `prompt://troubleshoot_install_failure` — encodes the audit_query → journal_search → get_system_health diagnostic chain so agents stop deriving it Tool-by-Tool. Optional app_id + since_minutes arguments parameterize the recipe; empty args yield a generic playbook.
- Session length is now configurable: set AccessTokenTTL (15m..24h, default 3h) and RefreshTokenTTL (1d..30d, default 7d) in the [security] section of user-service.conf. Out-of-range values fall back to the default with a startup warning.
- Custom App form: new "App Name (Project)" field edits the compose project `name:` (the app's identity) with a hint that reusing a name updates the existing app.
- App Store and Launchpad show a "Docker is not available" banner with install commands and docs links when the Docker daemon is missing or not running, instead of a silent empty list.
- Files: the folder listing (`GET /v1/folder`) now returns a server-classified `type` (video, audio, image, text, pdf, archive, blob), `extension` and `is_symlink` per entry plus `num_dirs` / `num_files`; the preview drawer uses `type`, so for example .mkv files now preview as video.
- PRIVACY.md lists every outbound call PowerLab makes (no telemetry), and Settings → About gains a "Privacy — no telemetry" card linking to it.
### Changed
- Settings → Catalog pane uses a new `<AsyncBoundary>` component for its loading / empty / sources branches. Pre-fix, the pane reinvented its own `{#if loading}{:else if empty}{:else}` cascade; post-fix the same state machine lives in `$lib/components/ui/AsyncBoundary.svelte` with locked precedence (error > loading > empty > children) and consistent a11y semantics (`role="alert"` on errors, `aria-live="polite" aria-busy="true"` on loading). The pane's external behaviour is unchanged — same data-testids, same copy, same chrome. Step 1 of the 5-pane sweep proposed in the 2026-06-02 UI audit; the other 4 panes follow in a separate PR once this one's visual regression-tested in production.
- Step 2 of the AsyncBoundary sweep — `AuditPane`, `LogsPane`, and `PowerPane` now share the same `<AsyncBoundary>` component that CatalogPane adopted in #673. `AsyncBoundary` gains a `variant` prop (`card` default + `inline` for table-cell rows) so the table panes (Audit, Logs) keep their borderless chrome while the card panes (Catalog, Power) keep their rounded-2xl chrome. Locked precedence (error > loading > empty > children) + a11y semantics (role=alert, aria-live=polite, aria-busy=true) now consistent across all four panes.
- powerlab-mcp: moved `glama.json` from `backend/powerlab-mcp/` to the repo root. Glama directory scanner looks at the repository root URL for this file (per the published glama.ai/mcp/schemas/server.json convention) — placing it under a subdir was a discoverability gap. Same content; just relocated.
- powerlab-mcp: enriched `search_docs` (309→698c) and `get_compose_conventions` (362→615c) descriptions — adds explicit Usage Guidelines + Contextual Completeness (when to use vs which alternative Tool). Lifts the per-tool minimum TDQS score from 4.35 to 4.85, which under Glama's 60% mean + 40% minimum weighting moves the Server TDQS to ~4.87 (estimated A tier).
- powerlab-mcp: enriched the 4 shortest tool descriptions (check_disk_free 210→514c, uninstall_app 218→441c, restart_app 240→519c, journal_search 259→566c). Each now spells out WHEN to call, common parameters/inputs, severity thresholds (disk), and explicit DO NOT use cases (restart for compose-yaml changes, uninstall without operator confirmation). Boosts Glama scorer signal + reduces agent trial-and-error.
### Deprecated
- In-product HTTPS (self-signed CA + Trust Onboarding flow that has been PR #43's evolved descendant since v0.2.7) is now deprecated. The flow stays functional through the v0.7.x patch line for operators already onboarded — gateway still binds `:8443` if a server cert exists from a prior install, and the Settings → Security pane still renders the per-OS install steps. New deployments should front PowerLab with a reverse proxy or cloud LB on the HTTP port (`:8765` panel / `:9090` MCP) instead. Six recipes shipped in `docs/operations/reverse-proxy.md` — Caddy (auto Let's Encrypt), nginx + certbot, Tailscale Funnel (no domain needed), Cloudflare Tunnel (no port-forward), cloud-managed LBs (AWS ALB / GCP HTTPS LB / Azure App GW), K8s Ingress + cert-manager. The Security pane carries a deprecation banner with the same pointer; the gateway logs a deprecation warning on every HTTPS spinup. Removal is roadmap (no specific version committed) — operators have several patch releases to migrate.
### Removed
- Deprecated label set: new app containers no longer get the legacy unnamespaced labels (`casaos=casaos`, `origin`, `icon`, `web`, `io.casaos.v1.app.store.id`, ...). They carry only the canonical `io.powerlab.v1.*` labels, which ends the ADR-0021 dual-write window. Containers that still have the legacy labels are still recognized and read.
- The installer no longer accepts the no-op `--allow-coexist` flag (a silent no-op since ADR-0021); passing it now fails with "Unknown argument", so drop it from runbooks.
### Fixed
- The upgrade-progress poll no longer overwrites an already-transitioned state when its in-flight fetch resolves late. Pre-fix, `poll()` only checked `state === 'restarting'` at function entry; if the timeoutTimer fired (or `reset()` was called) DURING the `await fetch(...)` or `await res.json()`, the poll's success branch would still execute and overwrite the new state with `success`. Audit-flagged as MEDIUM-severity manual-timer hygiene; turned out to be a real (low-probability) race with the 5-minute upgrade timeout. Fix re-checks `this.state` after each await and bails if the store has moved on. Regression locked by a deterministic test that mocks a deferred poll fetch and mutates state externally before resolving — verified RED on the pre-fix code, GREEN post-fix.
- The app-install pre-flight no longer misreads IP-bound compose ports: `127.0.0.1:8080:80` was probed as host port 127 because the page took `split(':')[0]`. Compose analysis (published host ports + compatibility warnings) moved from inline `as any` code in the Apps page into a typed, unit-tested `composeAnalysis` module that handles IP-bound and bracketed IPv6 bindings, `/udp` suffixes, host-port ranges (every port collected), `${VAR:-default}` interpolation (best-effort) and long syntax with string `published`. Container-only ports (`"80"`) are no longer probed since Docker assigns them an ephemeral host port. The settings page lost its whole-file exemption from the raw-fetch lint ban: "Reset trust" now goes through the shared API client (JWT + cookie), and the remaining raw calls (public cross-origin trust probes, binary CA download) carry per-line justified exceptions. Files-API success checks use a typed `isApiSuccess` helper instead of an `as any` cast.
- powerlab-mcp: an oversize POST to `/mcp` (over 1 MiB) now gets `413 Payload Too Large` instead of a generic `400`, both for a declared Content-Length and for chunked bodies.
- `docker://networks` (`/v2/app_management/docker/networks`) now fills `attached_containers[]` on real installs: members come from ContainerList's per-container network settings, since the daemon's network listing leaves them empty.
- powerlab-mcp: `journal://` resources and the sensitive-tier `journal://system/*` streams no longer drop entries whose MESSAGE journald emits as a byte array (binary or non-UTF-8 payloads); the bytes are decoded to text.
- Services verifying JWTs no longer hang when the user-service is slow: the JWKS public-key fetch now times out after 5 seconds.
- The one-line installer (`curl … | sudo bash`) now stops before downloading when Docker is missing, with a distro-specific install hint, matching the bundled installer, instead of printing a dim "Continuing" line.
### Security
- powerlab-mcp: the unauthenticated `/version` endpoint now returns only `{"version"}`; the commit hash and build date moved to the auth-gated `system://build` MCP resource so LAN hosts can no longer fingerprint the exact build.
- powerlab-mcp: the HTTP listener now sets ReadTimeout (30s) and IdleTimeout (120s) to bound slow clients, and audit records for proxied loopback requests carry the real peer address instead of the internal 192.0.2.1 sentinel.
- Files: downloads and previews (`/v1/file`, `/v1/batch`) now send `Content-Security-Policy` and `X-Content-Type-Options: nosniff`, so an uploaded .html or .svg cannot run script in the panel origin, and `Content-Disposition` actually reaches the browser with an RFC 6266 `filename*=` so non-ASCII names (e.g. relatório.pdf) download correctly.
- Backend dependencies bumped to clear the reachable vulnerabilities the govulncheck gate reports as of 2026-10: golang.org/x/image v0.43.0 (TIFF decoding DoS/panic), golang.org/x/text v0.39.0, kin-openapi v0.144.0 (request-validation panic and deepObject resource exhaustion), gorilla/websocket v1.5.3, rclone v1.75.0 (local-storage), and in app-management containerd v2.2.9, grpc v1.83.1, OpenTelemetry v1.45.0, go-getter v1.8.6 and in-toto v0.11.0. Six advisories whose only fix needs Go 1.26 or the docker v29 stack (x/crypto/ssh, rclone v1.75.1, buildkit, moby/go-archive) are allowlisted with justification until those moves land. CI also pins govulncheck and deadcode to Go 1.25-compatible releases (the @latest builds now need Go 1.26 and either failed or silently skipped), stops failing Dependabot PRs and `skip-changelog` PRs on the changelog-fragment check, and cancels superseded PR runs.
### Internal
- Added `scripts/check-dep-health.sh` and a weekly, report-only "Dependency health" workflow (ADR-0042). Both flag direct Go dependencies whose release in use is more than 24 months old or that are behind a newer minor or major version.
- Backend tests share one goleak helper (`backend/common/utils/testutil`) with the common ignore options (HTTP keep-alive loops, opencensus worker, go-socket.io accept loop) instead of copying `IgnoreTopFunction` strings into each test file. Leak checks behave exactly as before.
- Removed the unused DelayedExecutor from backend/common/utils; it had no callers and a time-unit bug that would have scheduled its timer about 158 years out.
- CI now runs the install smoke (fresh install + upgrade boot test, amd64 and arm64) on Dependabot pull requests, so a dependency bump that breaks service boot is caught before merge rather than after.
- app-management: install-time host resolution reads the network interfaces and hostname through package-level seams, so tests now cover every fallback (LAN IP, `hostname.local`, nothing resolves) and the error paths when the secrets file cannot be written. Runtime behaviour is unchanged.
- App Store page: the install-confirm (port-conflict) and app-detail modals are extracted into InstallConfirmModal and DetailModal components with their own tests; no behaviour change.
- Regression test: the app-management OpenAPI validator accepts `PUT /compose/{id}/status` with a bare JSON string body (`"stop"`/`"start"`/`"restart"`) and rejects the object form (`{"status":"stop"}`) that froze the UI in v0.1.x.
